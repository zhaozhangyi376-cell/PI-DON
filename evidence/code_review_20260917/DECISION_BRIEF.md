## 什么仍可保留

- 已保存且身份可核对的模型、原始预测/目标和轨迹，仍是研究资产，不删除、不原位改写。
- 当前真空介质参数并未因 F01 改变；两套 Yee curl 的方向/交错差分通过了独立线性场小反例，但这不是全问题解析精确性的证明。
- 真实已记录的残差失败、分量门失败和未完成状态保留。验收器不完整不能把这些旧FAIL改判。
- 旧 DCO 在特定测试合同下的低误差仍可作为算子学习证据；跨配置改善倍数必须用共同题目、相同归约重新核实，不能只比较同名数字。
- 无法从当前审查推断“论文方法无效”，也无法推断“换一轮训练就一定能达到论文结果”。

## 建议批准顺序

1. **验收与报告修复包**：补完整性/非有限值/身份/预算负面测试，拆分工程交付、科学判据和恢复资格；更正有原始证据支持的错误解释。只读取原权重，新报告另存。
2. **恢复与部署修复包**：保护终态、原证据和预算，修CLI和checkpoint故障窗口；通过临时目录故障注入后才能用于正式续跑。
3. **物理与模型使用合同包**：材料、abs/rel、尺度还原、独立盲测。先由你选择是否要研究非真空，以及第一阶段哪个实现合同作为主线。
4. **新实验与性能包**：上述合同确定后，再冻结一组共同试卷的最小鉴别实验。先profile再优化，不放宽门槛、不删除记账来换速度，不直接启动1024/8192。

这四包不是现在自动开工的授权。你决定范围后，再登记实施和验证；服务器正在训练的任务本次没有被修改、中止或重启。

修复以仍在使用的入口为先，不是把所有归档脚本都重写。历史源码快照保留原样，已封存脚本的问题用旁置说明限定影响；新验证和纠正报告进入新目录。

本轮主要是源码、已有记录及最小反例审查，没有把每个旧模型重新训练或全量重推理。交付时 `direct_mechanism_v1/runs/` 已部分存在，但四份M2摘要仍缺失；不自行恢复、不据缺件写成从未运行。最后完整根测试153次执行有1个paper01导入错误，独立_01的8项通过，harness仍缺上述四份摘要；153次执行还含重复收集，测试绿色本身也不能认证科学PASS。
